# Модель безопасности U7 Astra

## Граница доверия

MTProto-сессия пользователя имеет права полноценного Telegram-клиента. Telegram не выдаёт сессию, технически ограниченную одним ботом. Ограничение на `u7_school_bot` реализовано приложением; при захвате процесса сервера атакующий может обойти его. AES-GCM защищает секреты при отдельной утечке БД, но не при одновременном доступе к БД и MASTER_KEY или памяти процесса. Нельзя обещать отсутствие утечек или взлома.

Перед подключением ученику явно показывается объём доступа. Для более строгой изоляции потребуется локальный мост на устройстве каждого ученика либо официальный API владельца бота. Эта версия — серверный сервис с доверенным администратором.

## Реализованные меры

- Открытая регистрация; пароли не меньше 12 символов. Регистрация не открывает тела материалов: сервер выдаёт их после проверки Telegram-прогресса.
- Scrypt N=131072, r=8, p=1, случайная соль; одновременно не более двух затратных проверок пароля.
- 256-битные веб-сессии в HttpOnly/SameSite=Strict cookies; Secure и префикс __Host- в production. В SQLite хранится SHA-256 токена. Скользящий срок 30 дней: успешный авторизованный запрос продлевает запись в БД и cookie. Истёкшие или отозванные сессии и запросы с неверным CSRF не продлеваются.
- Проверка точного Host и Origin, обязательный JSON и custom header; для авторизованных изменений дополнительно CSRF-токен, связанный с веб-сессией.
- Ограничение запросов по IP и сохраняемые в SQLite ограничения попыток входа по аккаунту. Недоверенным X-Forwarded-For приложение не доверяет.
- Перед подключением/отзывом Telegram, сменой пароля и отзывом чужих веб-сессий повторно проверяется пароль кабинета. Пароль Telegram/коды не записываются в БД или логи.
- Случайный IV AES-GCM для каждого секрета, AAD с назначением и ID пользователя: шифротекст одного ученика не подходит другому.
- Все Telegram-операции определяют пользователя из серверной сессии. Нет RPC-прокси, произвольного peer ID или callback_data во входном API.
- Кнопки выдаются как короткоживущие случайные разрешения, привязанные к ученику и браузерной сессии. Перед отправкой сообщение и клавиатура повторно читаются из Telegram и сравниваются.
- Неопределённый результат нажатия записывается до сетевого запроса и блокирует повтор даже после рестарта. При подтверждённом ответе есть окно подавления повторов. Это не гарантия exactly-once на уровне сети/Telegram: транспорт может восстанавливать соединение, и окончательную идемпотентность обеспечивает бот.
- Чувствительные ответы no-store; CSP без inline-скриптов и внешних ресурсов, запрет встраивания в iframe, HSTS в production, referrer-policy=no-referrer.
- React экранирует текст, react-markdown не исполняет HTML. URL кнопок разрешают только HTTP(S) без логина/пароля, новые вкладки используют noopener/noreferrer. Внешние картинки не загружаются. Код учебных заданий отображается, но не запускается.
- В браузер не выдаются API Hash, MASTER_KEY или Telegram-сессия. Секреты не хранятся в localStorage.
- Аудит хранит название действия и время, без содержания чатов. Срок хранения 90 дней. Сообщения Telegram не сохраняются на диск, но Telegram-клиент может временно получать обновления аккаунта в памяти; приложение не выводит другие чаты.
- Зависимости закреплены lockfile; Telegram-библиотека закреплена точной версией. Сборка не требует запуска install-скриптов пакетов. Проверки зависимостей нужно повторять перед развёртываниями.

## Чего нет

- Независимого пентеста, формальной сертификации и доказательства отсутствия уязвимостей.
- Ограничения Telegram-ключа одним ботом на стороне Telegram.
- Поддержки любых возможных дополнительных email/captcha-проверок Telegram, медиа-загрузок, опросов, платежей и Web Apps. Для специальных элементов есть переход в официальный Telegram.
- Автоматического восстановления пароля по email, SMS-рассылок и подтверждения адреса email. Пароль можно изменить из действующего кабинета.
- Защиты от скомпрометированного устройства ученика, вредоносных расширений, администратора с доступом к ключам или захвата VPS.
- Синхронизации всей прод-БД или гарантированного совпадения публичной библиотеки со снимком конкретного учебного потока.

## Перед доступом реальных учеников

Настройте HTTPS и домен, проверьте серверные права и резервные копии, используйте отдельные секреты production, включите мониторинг инфраструктуры без записи request body/cookies, проверьте вход/отзыв/выполнение на тестовом аккаунте и организуйте независимый аудит. Не копируйте Telegram-сессию в другие приложения. Соблюдайте Telegram API Terms и применимые требования к хранению персональных данных.

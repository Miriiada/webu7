# U7 Astra

Самостоятельный веб-интерфейс для учеников `@u7_school_bot`. React + TypeScript, Node.js 24, Express, SQLite и Telegram MTProto (teleproto). Исходный бот изменять не нужно.

**Развёртывание на Ubuntu с существующим Nginx, адрес `https://u7-hub.kz/web/` и обновления из Git:** [пошаговая инструкция](deploy/README.md). Для этого варианта не запускайте Caddy из compose.yaml: HTTPS обслуживает существующий Nginx.

На проверенном `kalki-server` основной сайт и бот работают в PM2. При подтверждённом доступе sudo рекомендуется отдельный пользователь и systemd из основной инструкции; [инструкция PM2](deploy/PM2.md) сохранена как альтернатива.

## Возможности

- Программа курса, поиск и чтение опубликованных уроков из репозитория U7.
- Личные кабинеты нескольких учеников, открытая регистрация.
- Вход по паролю без второго фактора. Cookie сохраняется 30 дней и продлевается при каждом успешном авторизованном запросе, в том числе после повторного открытия браузера.
- Подключение своего Telegram по номеру, коду и облачному паролю при его наличии.
- Получение сообщений и реальных inline-кнопок только от бота школы.
- Подтверждение каждого нажатия и отправки сообщения; повторная проверка кнопки на сервере.
- Обновление ответов каждые 15 секунд, пока открыта главная или страница связи с ботом. После отключения соединение не поддерживается.
- Изменение имени, пароля, завершение других сессий, отзыв Telegram-авторизации, журнал безопасности.

У сайта нет собственной отметки «выполнено»: состояние обучения определяет бот. Просмотр материала из библиотеки не означает, что этот шаг уже выдан ученику. Текущий прогресс показывается в сообщениях бота; полную базу прод-сервера Telegram API не предоставляет.

## Локальный запуск

Установите **Node.js 24 LTS**. В папке проекта:

```sh
npm ci --ignore-scripts
npm run build
npm run setup
npm start
```

Откройте `http://127.0.0.1:4173` и создайте кабинет. Затем подключите Telegram. Названия уроков и шагов открыты; содержимое выдаёт сервер по подтверждённому прогрессу бота.

На этом компьютере стандартная команда npm ссылается на повреждённую установку, а системный Node имеет версию 23. Для уже подготовленной рабочей копии есть Windows-помощник, выбирающий Node 24 из установленного окружения Codex:

```powershell
.\scripts\windows.ps1 -Action start
```

Доступны также `build`, `test`, `setup`, `sync`. Для переносимой установки на другом компьютере используйте обычный Node.js 24 LTS и команды npm выше.

`setup` создаёт `.env` со случайным ключом шифрования. Повторный запуск не заменяет существующий ключ. Не удаляйте ключ при наличии подключённых аккаунтов. В текущей рабочей копии `.env` уже создан; в архив он не включается.

## Подключение Telegram

1. Получите **API ID и API Hash приложения** на [my.telegram.org](https://my.telegram.org/apps). Это не токен бота; токен `@u7_school_bot` не требуется.
2. Заполните `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` в `.env` локально. Не отправляйте значения в чат, GitHub или браузерные настройки.
3. Перезапустите сервер и войдите в кабинет с паролем.
4. Нажмите «Подключить Telegram». Потребуются пароль кабинета, номер телефона, затем код Telegram и, при необходимости, облачный пароль.
5. Откройте «Связь с ботом». Если сообщений нет, подтвердите отправку `/start`. Для выполнения текущего задания нажмите реальную кнопку бота «Выполнено» и подтвердите действие.

Telegram иногда требует дополнительные проверки email/капчи; эти ветки в этой версии не реализованы и не обходятся.

Имя бота фиксировано серверной настройкой `TELEGRAM_BOT_USERNAME=u7_school_bot`. После первого разрешения имени числовой ID закрепляется в SQLite. Для строгой проверки с самого начала администратор может заранее задать проверенный `TELEGRAM_BOT_ID`. Пользователь не может подставить другой чат, callback-данные или произвольный Telegram RPC.

## Развёртывание с HTTPS

Нужен собственный VPS/сервер с Docker Compose и доменом. Этот сервис использует постоянные MTProto-соединения и SQLite; обычный статический хостинг или Cloudflare Worker не подходит. Проект не опубликован на внешний сервер автоматически.

1. Скопируйте исходники на доверенный сервер. Закройте прямой доступ к Node.js извне, оставьте входящие 80/443 для Caddy.
2. Скопируйте `.env.example` в `.env`, создайте новый 32-байтный ключ на сервере и запишите его в `MASTER_KEY`. Например: `node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"`. Не используйте ключ разработки в другом окружении.
3. Задайте `APP_ORIGIN=https://school.example.org`, `SITE_DOMAIN=school.example.org`, API ID/Hash. `school.example.org` замените своим доменом; его DNS должен указывать на сервер.
4. Ограничьте доступ к `.env` владельцем (`chmod 600 .env` в Linux), не публикуйте его. На Windows используйте ACL пользователя сервиса для `.env` и `private/`: POSIX-права там не обеспечивают изоляцию.
5. Запустите `docker compose up -d --build`. Caddy получает сертификат и проксирует запросы. Node.js не публикует свой порт на хост.

В Compose задан точный доверенный адрес прокси `172.30.71.2`, чтобы ограничение запросов учитывало адрес ученика. Не заменяйте его на доверие всем прокси. Если этот диапазон занят, измените одновременно subnet, адрес Caddy и TRUST_PROXY. Не подключайте посторонние контейнеры к сети backend.

Запускайте **один процесс приложения и одну реплику**. Блокировки действий, разрешения кнопок и незавершённый вход находятся в памяти процесса. Для горизонтального масштабирования нужна отдельная архитектура с общей очередью и хранилищем блокировок. Docker-конфигурация подготовлена, но в этом окружении не запускалась.

## Синхронизация с репозиторием

```sh
npm run check:upstream
npm run sync:content
npm run build
npm test
```

Скрипт получает SHA `main`, скачивает четыре JSON-файла **по этому SHA**, проверяет формат, оставляет опубликованные материалы и атомарно заменяет `data/catalog.json`. Он не исполняет исходный код репозитория и не касается базы учеников. Входящие HTML-теги и внешние изображения не исполняются/не загружаются в просмотре материалов.

В `.github/workflows/content.yml` есть ежедневная сборка проверенного снимка в артефакт GitHub Actions. Она заработает после помещения проекта в собственный репозиторий с включёнными Actions. Снимок нужно проверить и включить в следующую поставку; автоматического обновления продакшена нет. Изменения кнопок бота видны через Telegram без копирования обработчиков. Изменение протокола Telegram или сценариев входа может требовать доработки адаптера.

## Проверка

```sh
npm test
npm run build
npm audit --omit=dev --audit-level=high
```

Тесты используют отдельную БД в памяти и подменённый Telegram-клиент. Внешних сообщений не отправляют. Покрыты межпользовательская изоляция, CSRF, регистрация, продление и истечение месячных сессий, шифрование, устаревшие кнопки, повторы и параллельные действия. Живой вход и выполнение задания необходимо проверить собственным тестовым учеником после настройки Telegram API. Успех модульных тестов не заменяет эту проверку и независимый аудит безопасности.

## Секреты, резервные копии и восстановление

- `private/astra.sqlite` хранит пользователей, зашифрованные Telegram-сессии, хеши паролей и веб-сессий, журнал действий. История чатов на диск не записывается. Email, имя и Telegram ID — незашифрованные метаданные внутри защищаемой БД.
- Резервируйте SQLite согласованным снимком: остановите приложение или используйте SQLite Backup API. Ключ храните отдельно от резервной копии БД. Проверьте восстановление в изолированной среде без живых Telegram-подключений.
- Потеря MASTER_KEY означает потерю доступа к зашифрованным секретам. Замена ключа без миграции данных не является ротацией.
- Если Telegram уже отозвал ключ и обычное отключение не работает: `node build-server/scripts/admin.js forget-telegram`, затем перезапуск. Перед забыванием сессии завершите устройство U7 Astra в официальном Telegram.
- При подозрении на компрометацию сервера остановите сервис и отзовите сессии U7 Astra в Telegram у всех затронутых учеников. Простого изменения пароля сайта недостаточно.

Ограничения и модель угроз описаны в [SECURITY.md](SECURITY.md). Материалы курса взяты из [a-kalki/u7-school](https://github.com/a-kalki/u7-school); права на них остаются у исходных авторов. Доступность репозитория не означает автоматического разрешения на любую перепубликацию: перед публичным запуском уточните условия у школы.

## Вход и месячные сессии (29 сентября 2026)

Двухфакторная защита кабинета удалена по требованию владельца. Существующие аккаунты, включая ранее настроившие TOTP, входят только по паролю. Старые зашифрованные TOTP-поля БД оставлены для совместимости схемы, но не читаются при входе. Пароли и Telegram-сессии не меняются. Уже истёкшие старые веб-сессии не восстанавливаются: после нового входа действует срок 30 дней.

При использовании сайта вход продлевается на 30 дней; закрытие браузера не завершает его. Фоновое обновление чата на видимой странице также считается использованием. Выход, смена пароля или отзыв сессии завершают доступ сразу. Сама Telegram-авторизация независима от срока cookie сайта и хранится зашифрованной до отзыва.

### Подключение Telegram через QR

Если код входа не приходит, выберите «QR-код — без SMS» в окне подключения. После подтверждения паролем кабинета отсканируйте QR через Telegram → Настройки → Устройства → Подключить устройство. Облачный пароль Telegram запрашивается, если он включён в аккаунте.

QR формируется локально сервером, не передаётся сторонним генераторам и обновляется по сроку Telegram. Попытка действует пять минут и привязана к кабинету и текущему браузерному сеансу. Изображение и токен входа не сохраняются в базе или журнале. Сохранение зашифрованной Telegram-сессии происходит после подтверждения входа.

### Прогресс и выполнение шагов

После входа с подключённым Telegram сайт восстанавливает прогресс из сообщений бота: при каждой синхронизации читает последние сообщения и ещё одну порцию старой истории. Подтверждённые шаги сохраняются отдельно для кабинета и Telegram-аккаунта. В базе сохраняются ID шагов и номера сообщений-оснований, а не переписка целиком.

Текущий урок сопоставляется по модулю, проекту, названию урока, названию и позиции шага. Неоднозначные или изменившиеся материалы не получают кнопку выполнения. Переход в следующий модуль не означает автоматического завершения предыдущего: счётчики показывают только подтверждённые уроки. Удалённая история и старые версии программы могут препятствовать полному восстановлению.

В текущем шаге «Выполнить» отправляет команду сразу, без диалога подтверждения. Галочка появляется после подтверждающего сообщения бота; сайт открывает следующий шаг. При переходе между уроками/проектами используется только реально полученная кнопка бота «Начать следующий урок/проект». Команды с неопределённым результатом автоматически не повторяются. Другие команды в разделе «Связь с ботом» сохраняют подтверждение.
